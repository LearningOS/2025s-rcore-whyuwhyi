# 实验说明

1. `sys_get_time()` 和 `syy_trace()` 本来均使用 `translate_byte_buffer()` 函数，但是在 `sys_trace()` 里使用 `translate_byte_buffer()`
时会出现错误，还是很逆天的错误，又一个测例使用最大整数作为地址，会让 `buffer` 数组开得特别大，直接堆分配失败，具体原因还没找到。
通过修改为 `ppn` 的 `get_byte_array()` 函数可以解决问题。

2. `mmap()` 和 `munmap()` 的实现逻辑是，在 `MemorySet` 中实现 `mmap_area()` 和 `munmap_area()` 函数，并开放接口给 `TaskManager`，
`TaskManager` 进一步封装这两个函数，最后将这两个函数开放，供其他函数调用。这两个函数的返回值是 `Result<()>`，表示成功或失败。

3. 在 `sys_mmap()` 和 `sys_munmap()`，首先对传入的参数进行初步检验，然后调用 `2` 中实现的接口。

# 简答作业

1.

10位保留位（必须为0），44位页框号，2位 `RSW` （保留位，必须为0） 以及8位标志位。

标志位包括：

- `D` ：Dirty，表示页面是否被修改过。
- `A` ：Accessed，表示页面是否被访问过。
- `G` ：Global，表示页面是否是全局页面。
- `U` ：User，表示页面是否是用户页面。
- `X` ：Executable，表示页面是否可执行。
- `W` ：Writable，表示页面是否可写。
- `R` ：Readable，表示页面是否可读。
- `V` ：Valid，表示页面是否有效。

2.

2.1

    指令缺页异常 (Instruction Page Fault)： 当 CPU 尝试从虚拟地址中取指令，而该地址未映射或无效时发生。

    加载缺页异常 (Load Page Fault)： 当 CPU 尝试读取数据而对应页面不存在时发生。

    存储/原子操作缺页异常 (Store/AMO Page Fault)： 当写入数据或进行原子操作时目标页面不存在或无效时发生。

2.2

    sepc ： 保存触发异常的指令地址。

    scause ： 指出异常类型，例如 Load Page Fault、Store Page Fault 或 Instruction Page Fault。

    stval ： 保存导致异常的虚拟地址。

2.3

    延迟分配：仅在页面首次被访问时才真正分配物理内存和建立页表映射，从而减少不必要的内存分配和页表操作。

    节省资源：如果一个进程申请了大块内存（例如 10G），但实际上只使用了其中很小一部分，
    Lazy 策略可以避免浪费大量物理内存和管理开销。

2.4

    按照 SV39 的三级页表策略，需要三级页表 2621440 个，二级页表 5120 个， 一级页表 10 个。（均为估算）
    共需要内存约 20MB。

2.5

    Lazy 策略实现：
    在进程创建时，不立即为整个映射区域分配物理页面和填充所有页表项，而是在页表中预留条目（例如标记为不可
    访问或带有特殊标志），当页面第一次被访问时，由缺页异常处理程序分配物理页面并更新对应的 PTE。

    缺页处理：

        缺页异常发生后，异常处理程序读取 stval 得到出错地址；

        根据缺页地址计算对应的虚拟页号；

        分配新的物理页面并建立映射；

        更新 PTE 为有效，并设置适当的权限；

        返回后重新执行出错指令。

2.6

    当页面被换出到磁盘后，操作系统会将对应 PTE 的 有效位 (V) 清零，同时在页表的保留位中保存该页
    的 swap 信息（如 swap 设备、偏移量等）。

    这样，PTE 虽然包含了某些信息，但因为 V=0，所以硬件认为页面不存在，进而触发缺页异常。

3.

3.1

    无论是单页表还是双页表，更换页表时只需要更新 satp 寄存器即可。

3.2

    在单页表设计中，内核空间映射在页表中，但这些映射对应的 PTE 中不会设置 U (User) 标志，即权限隔离。
    用户无法访问内核空间（若访问，则产生 Page Fault）。

3.3

    效率高：
    单页表下上下文切换时无需切换页表，减少了 satp 寄存器的修改和 TLB 刷新开销。

    实现简单：
    只维护一张页表，系统整体设计较为简单；

    资源共享：
    内核映射对所有进程都是一致的，便于内核代码和数据共享。

3.4

    双页表应用内核各自拥有独立的页表。进入内核态时，必须切换到内核页表，离开内核态时切换回用户页表。
    不同应用程序之间的页表是独立的，在应用程序之间切换页需要切换页表。

    而单页表只有不同应用程序之间切换时需要切换页表。
