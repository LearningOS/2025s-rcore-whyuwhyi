# 实验说明

1. 本次实验有点像 `OS` 课设里面写的死锁避免机制——优先级捐赠。不过在这里更简单一点，
其实只要按照算法的要求储存需要用到的资源即可。

2. 具体的，每个 `process` 储存剩余的 `semaphore` 资源，每个 `task` 需要储存自己持有的锁，
自己持有的信号量，以及导致自己阻塞的锁和信号量。

3. 有坑的地方，就和很容易出现 `borrow mut error` ，我对 `Rust` 的相关数据结构还是不是
很熟悉。另外最开始的时候，我直接将 `semaphore` 的 `count` 作为系统剩余资源量，吃了不少苦，
写了一堆 `print!` 才找到问题。

# 简答作业

1.

-
    1. 首先将当前线程从处理器管理结构 PROCESSOR 中移除，随后在线程控制块中记录退出码并回收当前线程的线程资源组 TaskUserRes。
    2. 将进程标记为僵尸进程然后记录进程退出码， 进程退出码即为其主线程退出码。
    3. 将子进程挂到初始进程 INITPROC 下面。
    4. 回收所有线程的 TaskUserRes。
    5. 清空子进程列表、回收进程地址空间中用于存放数据的物理页帧、清空文件描述符表。
    6. 移除除了主线程之外的所有线程，主线程的内核栈需要父进程回收。
-
    1. 在调度程序中。（需要回收）
    2. 在进程管理程序中（包含一系列函数），父子关系引用，以及本实验设计的死锁检测函数等。（不需要回收）
    3. 在各种同步原语的等待队列。（需要回收）

2. Mutex1 采用了循环检查的设计，确保了只有当锁真正可用时，lock() 才会返回，满足互斥锁的正确语义。
Mutex2 则采用单次检查的方法，如果锁被占用就挂起当前任务，但唤醒后直接返回，未能再次检查锁状态，
可能导致任务错误地以为自己持有锁，从而引发数据竞争、破坏互斥性甚至死锁问题。
